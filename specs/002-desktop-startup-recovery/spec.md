# 功能规范 · 桌面独立启动与会话接续

**来源** [Issue #2](https://github.com/wqyxy/codex_bridge/issues/2)

1. **AC1** 记录原部署的桌面与后台 PID、父进程、8766 监听、计划任务和脱敏日志。在 Cockpit Tools 切换前后采样，核对后台退出原因。
2. **AC2** 现有部署可停用项目创建的登录任务，按变更前的记录恢复用户级环境变量和 ChatGPT 启动选项。Bridge 的启动、停止和异常退出独立于官方启动流程，保留会话、网页凭据和其他用户配置。实机覆盖 Windows 冷启动、官方启动和登录、A → B → A 切换。
3. **AC3** Windows 桌面端持有打开的测试会话，用户从手机发送后在两端看到原会话 ID、输入和回复。只有确认桌面端当前持有会话时才能发送。关闭、断开或不兼容时显示原因并保留草稿。发送结果未知时，标明待确认并禁止直接重发。
4. **AC4** 桌面账户变化使旧接续授权失效。手机重新确认接续对象，网页登录独立有效。展示的模型和额度属于当前桌面账户。
5. **AC5** AC3 通过后，对照桌面与手机验收实时进度、活动轮次的补充指令、待审批事项及审批结果。记录桌面版本、自动化覆盖与实机证据。

桌面 IPC 不兼容时评估官方 SSH 远程项目，以两端均连接同一远程 App Server 且原会话 ID 可以往返作为通过条件。
