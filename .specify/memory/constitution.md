# codex_bridge 项目章程

## 核心原则

### 一、先明确需求
每个新功能都应在 `specs/<feature>/spec.md` 写明用户目标和可验证的验收标准。实施计划和任务应与该规范一致。

### 二、保持实现范围最小
围绕已确认的任务修改。新增依赖或扩展时，应在计划中说明用途和取舍。

### 三、验证交付
完成任务时验证相应的验收标准，并记录已执行的检查以及仍待验证的内容。

## 维护

修改原则时更新版本与修订日期，并检查受影响的规范和计划。
