# 实施计划 · 局域网 Codex 控制台

**规范** [spec.md](spec.md)  
**环境** Windows、Node.js 24、Codex CLI 0.153.2

## 方案与章程核对

使用 Node 标准库和浏览器原生模块。HTTP 服务负责配对、工作目录白名单和同源请求校验。Bridge 默认通过标准输入输出连接本机 App Server，也可通过主机回环 WebSocket 连接外部管理的共享 App Server。前端使用中文响应式界面，采用独立布局。运行时无需第三方依赖。

从需求 AC1–AC7 派生实施任务，按真实协议检查并记录实际验证。局域网服务绑定到主机显式选择的 IPv4 和对应子网，设备授权状态保存在桥接进程内。

## 源代码

- src/rpc.mjs 管理两种传输的 JSON-RPC 消息、请求超时和连接生命周期。
- src/bridge.mjs 管理会话、临时流式快照、交互和重连。
- src/legacy.mjs 检测 Windows 旧版历史文件的写入状态。
- src/access.mjs 管理登录限速、设备授权和监听边界。
- src/credentials.mjs 将用户名及加盐的 scrypt 密码摘要保存在主机用户数据目录。
- src/server.mjs 提供同源 HTTP 和 SSE。
- public/ 提供浏览器界面。
- test/ 验证复连、协议映射、审批去重及访问边界。

参考项目版本与技术取舍见 [research.md](research.md)，已执行验证见 [verification.md](verification.md)。

用户名和密码可供多台设备使用。登录会话由每台浏览器的 Cookie 单独标识。

网页修改密码需要同源会话和当前密码校验。新密码使用随机盐重新计算摘要，以原子替换保存，保存成功后撤销其他设备授权。

项目列表使用官方 App Server 的只读项目目录和会话归属。未分配的历史按匹配项目根目录或工作目录整理。展开原生项目时按该项目独立分页。浏览器在本地保存展开状态。

项目显示顺序、置顶项目和旧项目归属来自桌面端的只读侧栏状态。使用当前桌面账户的排列并以 App Server 的置顶区获取本机置顶对话。仅向已登录的浏览器返回需要显示的字段。

Windows 启动时优先使用桌面版随附的 Codex CLI，允许主机通过显式路径选择其他安装。模型、推理强度和速度从所选 App Server 的运行时目录读取。

对话界面采用冷灰配色和较紧凑的侧栏。Markdown 通过浏览器 DOM 构建，保留文本并过滤可执行链接。未读状态来自 App Server 回执，采用带版本的标记已读操作，避免覆盖尚未读取的新回复。

通过 `--app-server-url` 选择共享后台。网页使用同一会话 ID 调用原生 `thread/resume` 和 `turn/start`。运行中的会话使用带轮次 ID 的 `turn/steer`。独立后台继续遵循 Codex 的单写入者约束，冲突时网页保留原会话和草稿。切换桌面端需要重新启动桌面应用，并验证桌面工具兼容性。

Windows 通过当前用户登录触发的任务启动共享后台。启动脚本等待回环服务就绪后打开桌面端，并在局域网地址可用时启动 Bridge。脚本核对已存在监听的进程与连接，避免重复启动。Bridge 和桌面都支持从 `CODEX_APP_SERVER_WS_URL` 读取默认地址。
